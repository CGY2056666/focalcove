# 专注评分和推荐时长是怎么来的

系统主要做三件事：**看屏幕内容是否和目标有关，给出反馈，再参考过去的记录推荐下一次做多久。**

下面都用“学习 Python”举例。

## 一 四项评分分别看什么

| 四项评分 | 一句话解释 | 例子 | 默认占比 |
|---|---|---|---|
| 目标相关度 | **看的内容对不对题？** | Python课程与目标有关，无关购物页面与目标关系不大 | 50% |
| 任务行为证据 | **有没有正在做事的线索？** | 画面有相关代码或学习材料，比只写着“我要学Python”更有说服力 | 25% |
| 工具与场景适配度 | **用的工具合不合适？** | 代码编辑器适合编程，但打开编辑器不代表一定在学习 | 15% |
| 无关内容干扰程度 | **无关内容有没有占据画面？** | 学Python时，无关购物内容占满屏幕，干扰程度就比较高 | 10%，反向计分 |

可以记成：**内容、行为、工具、干扰。**

前三项越高越好，第四项越低越好。每项先打0—4级，再由程序合成总分。模型没把握时，程序会把分数往50分靠，不轻易给出极高分或极低分。

这四项有区别：**打开了合适的工具，不代表已经出现学习行为；出现了学习行为，也要看学的是不是本轮目标。**

例如，屏幕只显示“学习Python”和倒计时，不能单凭这些就判定用户正在学习。

## 二 有哪些心理学依据

最容易理解的是下面三个思路。它们可以解释“为什么这样设计”，但没有直接验证本系统的四项评分或权重。

### 1 先说清楚要做什么 才知道有没有跑题

目标设置理论认为，明确的目标能帮助人把注意和行动放到要做的事情上。

所以系统先问“这轮要做什么”，再看屏幕内容是否服务这个目标。比如，目标是学Python，看编程教学视频可以与目标相关，不能因为打开视频网站就一律判为分心。

依据：Locke与Latham（2002），[目标设置理论综述](https://www.wku.edu/cebs/doctorate/documents/readings/locke_latham_2002_building_useful_theory.pdf)。

### 2 做完回头看一看 下次更容易调整

自我调节学习可以简单理解成：**先做计划，过程中留意自己的表现，结束后回顾，再调整下一次计划。**

系统设置目标、记录画面、给出反馈、调整下轮时长，借鉴了这个思路。目的是给用户提供回顾线索，而不是只告诉用户一个分数。

依据：Zimmerman（2002），[自我调节学习概述](https://doi.org/10.1207/s15430421tip4102_2)。

### 3 切换了事情 注意不一定马上跟着切换

注意残留研究发现，人从一件事转去做另一件事时，注意可能还部分停留在上一件事上，影响接下来的表现。

这可以解释为什么要关注无关内容和不必要的切换。不过，系统看到一张无关截图，并不能据此确认用户发生了“注意残留”。

依据：Leroy（2009），[任务切换与注意残留研究](https://doi.org/10.1016/j.obhdp.2009.04.002)。

### 写进介绍材料 可以这样说

> 系统参考目标设置、自我调节学习和注意残留研究，帮助用户明确目标、回顾屏幕上的任务线索，并根据个人历史记录调整下一轮计划时长。

需要保留一句说明：**这些研究支持设计思路；四项评分、各项占比和具体推荐时长，还需要用实际用户数据验证。**

尤其是“工具合不合适”这一项，目前没有在所引研究中找到对本系统评分方式的直接验证。它是产品用来辅助理解画面的一个判断角度。

## 三 分数代表什么

**分数表示屏幕上呈现的内容与本轮任务有多相关。**

它不能直接说明用户心里有多专注，也不能说明学会了多少。比如，屏幕一直停在课程页面，系统也无法仅凭画面确认用户是否理解了课程。

除分数外，系统还区分四种情况：

| 情况 | 通俗解释 |
|---|---|
| 专注 | 有比较明确的目标相关线索，判断把握和连续证据也达到要求 |
| 不确定 | 看得清画面，但证据不足，不能肯定是否在做目标任务 |
| 分心 | 有比较明确的无关内容线索，判断把握和连续证据也达到要求 |
| 待复核 | 图片无效、模型超时等，暂时无法判断 |

当前界面可能把“不确定”显示为“轻微偏离”，但它不等于分心。“待复核”也不等于用户得了0分。

## 四 下一次做多久 是怎么推荐的

### 刚开始 先推荐25分钟

可靠记录不足3次时，系统先推荐25分钟。**这是当前设置的起点，不是心理学证明人人都最适合25分钟。**

### 有了记录 参考你过去能连续做多久

系统优先找同一个目标的记录；不够时，再找同一类目标的记录，最多参考最近10次。

它会看每次最长连续专注了多久，找一个比较有代表性的中间时长，并更重视近期表现。这样，一次特别长或特别短的记录不容易完全决定结果。

这里的“连续专注”仍是根据画面判断的连续目标相关状态，不是直接测量人的注意力。

### 做完这一轮 再小幅调整

在可靠记录足够、本轮数据也可靠时，通常这样处理：

| 这一轮表现 | 下一轮建议 |
|---|---|
| 做到了至少90%的计划时间，且画面评分至少75分 | 参考过去表现，保持或增加一点，通常最多加5分钟 |
| 做到的时间不足计划的70%，或者画面评分低于50分 | 通常减5分钟，受最短时长限制 |
| 处于中间情况 | 保持当前时长 |

如果可靠历史还不足3次，下轮仍先推荐25分钟。如果历史已经足够，但本轮数据不可靠，就按当前计划取整后保持。

推荐通常按5分钟一档，默认在5—180分钟之间。手动选了非5倍数时长时，取整会让实际调整幅度有所不同。

“做到了90%的计划时间”只表示**计时长度达到了90%**，不表示学习任务完成了90%。

25分钟起步、每次调整5分钟，以及70%、90%、75分这些数字，都是当前程序的规则，并非上述心理学研究直接得出的最佳数值。

## 五 为什么有时不调整时长

**数据太少或太不确定时，先不急着据此调整。**

程序要求：截图采集和分析足够完整，有可用平均分，至少有3张不是重复复用的明确画面，而且明确状态占可分析时长的一半以上。有效覆盖率还要达到70%，评分版本也要符合当前要求。

这些是数据质量门槛，不是心理学诊断标准。“数据可靠”也不等于“表现好”：证据充分的低分记录，同样可以用来帮助调整计划。

## 六 大模型要按什么格式回答

可以把模型的回答理解为一张固定的小表格：

| 模型要交出的内容 | 包含什么 |
|---|---|
| 场景判断 | 与目标有关、证据不足，还是明显无关 |
| 场景名称 | 例如“代码编辑页面” |
| 四项评分 | 内容、行为、工具、干扰，各0—4级 |
| 判断把握 | 0—1，越高表示模型越有把握 |
| 一句理由 | 说明画面里看到了什么 |

合计八个字段。**模型负责描述画面，程序负责检查、算总分和推荐时长。**

回答缺项、数值不合规或请求失败时，系统会标为待复核。模型说“与目标有关”，但评分又缺少必要证据时，程序会改为证据不足。

固定格式能让回答更方便检查和处理，但格式正确，不代表判断一定正确。

# 评分、推荐时长与大模型输出规则（按当前代码整理）

核对日期：2026-10-20。范围：当前工作区服务端实现，包含实时会话、最终历史记录与推荐调用链。本文描述已有行为，不修改算法。数值若无特别说明均为代码默认值；外部评分策略和环境变量可能覆盖部分参数，本文未确认正在运行的进程配置。

## 1. 总体调用关系

截图 → 视觉模型八字段 JSON → 类型与范围校验 → 类别/维度一致性保护 → 服务端合成分数 → 时间平滑与四态判定 → 按时间汇总 → 可靠性判定 → 积分与下一轮推荐。

- 当前评分版本：`multidim-v1`。
- 评分评价的是“画面任务相关度”，不能据此确认用户心理专注、真实任务完成质量或学习效果。
- 模型不计算总分，不决定推荐分钟数。总分由服务端计算；推荐由本地确定性算法计算。
- `completion_score` 保存的是会话平均画面任务相关度，并非实际任务完成百分比。
- 百炼 `BailianVlmScorer` 继承 `SiliconFlowVlmScorer`，复用同一输出协议与校验规则。

代码：`focus_engine/vision_provider.py`、`siliconflow_vlm.py`、`scoring.py`、`session.py`、`app/helpers.py`、`app/services/focus_session_service.py`。

## 2. 大模型结构化输出

### 2.1 输入与八字段协议

输入包含系统提示词、当前目标、最多10条核心线索、8条相关场景线索、6条可能无关线索，以及截图。目标经空白规范化后最多保留160字符；负面线索必须结合目标解释。

```json
{
  "category_type": "focus",
  "category_label": "Python代码编辑",
  "goal_relevance": 4,
  "task_evidence": 3,
  "context_fit": 4,
  "distraction_level": 0,
  "confidence": 0.9,
  "reason": "画面显示正在编写与目标相关的Python代码"
}
```

| 字段 | 类型与范围 | 含义 |
|---|---|---|
| category_type | focus / neutral / distract | 有明确目标证据 / 证据不足或通用界面 / 有明确无关证据 |
| category_label | 非空字符串 | 场景标签 |
| goal_relevance | 0–4整数值 | 主体与具体目标的相关程度 |
| task_evidence | 0–4整数值 | 阅读、编写、检索、操作或产出的可见证据 |
| context_fit | 0–4整数值 | 应用、网页、工具对完成目标的适合程度 |
| distraction_level | 0–4整数值 | 无关内容在画面中的主导程度，越高越不利 |
| confidence | 0–1有限数 | 模型判断置信度 |
| reason | 非空字符串 | 简短中文可见证据说明 |

统一维度锚点：0=完全没有或相反；1=弱；2=一般或无法确认；3=明确；4=直接且充分。

提示词要求只输出 JSON，不输出总分、Markdown、OCR全文、思考过程或额外字段。娱乐、购物若本身就是目标，不应仅凭页面类型判分心。空白页、欢迎页、无任务内容的IDE/文件管理器、仅有目标网站类型而无具体内容的页面，应判 neutral。neutral 不等于分心。

### 2.2 服务端实际校验

- 顶层必须为对象，八个字段必须齐全。
- 类别会去掉首尾空白并转小写，只接受三种枚举。
- 场景标签与理由必须为非空字符串；不硬性验证中文、一句话或字符长度。
- 维度接受数值类型但要求数学意义上为整数，因此 `3.0` 可通过；字符串 `"3"`、布尔值、小数、越界、非有限数均不能通过。
- confidence 必须为有限数字且在[0,1]内，拒绝字符串和布尔值。通过后归一化时保留3位小数。
- 提示词禁止额外字段，但校验器不拒绝额外键；它们不会成为评分证据。旧OCR、关键词、语义分等额外字段均被忽略，兼容字段保留空值或0。

### 2.3 类别保护

| 模型请求类别 | 必须满足的维度条件 | 不满足时 |
|---|---|---|
| focus | goal_relevance≥3，task_evidence≥2，distraction_level≤1 | 降为neutral |
| distract | distraction_level≥3，goal_relevance≤1 | 降为neutral |
| neutral | 无额外升级规则 | 保持neutral |

维度满足条件也不会将模型的neutral自动升级为focus/distract。类别冲突降级后仍可评分，不等于调用失败。

专注小窝自身页面保护：服务端根据模型的category_label与reason识别计时器/自身页面，将task_evidence限制为至多1。只有目标明确涉及开发或测试专注小窝，并且模型描述含实际开发证据，才例外。这里依赖模型的文字说明，并非服务端重新读图或OCR。原始模型类别和四维值保留在score_breakdown供审计。

### 2.4 请求、解析与失败

- 使用 `response_format={"type":"json_object"}`，不是供应商侧严格JSON Schema；字段约束主要由本地校验实现。
- 默认temperature=0、max_tokens=300、enable_thinking=false。token配置被限制在80–300；模型请求超时最多16秒，帧截止最多17秒，采集周期默认20秒。
- 实时帧只发起一次请求，不进行失败重试。先解析content；为空时尝试reasoning_content；直接JSON解析失败时提取第一个闭合JSON对象重试，因此实际解析器容忍包裹文本/代码块。
- 缺字段、类型非法、超时、HTTP错误、解析错误、未配置密钥均进入待复核/unscorable。组件为null，不以假分参与会话平均。内部兼容字段focus_score可能为0，不能解释为“用户得0分”。
- 有效结果可以缓存，待复核结果不缓存；缓存键包含规范化目标、模型、评分版本与实际JPEG内容摘要。

代码：`siliconflow_vlm.py::SYSTEM_PROMPT`、`_build_text_prompt`、`_request_completion`、`_post_chat_completion`、`_validate_response`、`_normalize_response`、`_gate_category`。

## 3. 评分计算

### 3.1 单帧基础分和置信度修正

设四维等级为g、e、c、d，均在0–4；置信度为q。

```text
G=25g，E=25e，C=25c，D=d/4
B=0.50G + 0.25E + 0.15C + 0.10×100×(1-D)
a=0.50+0.50q
S=50+(B-50)×a
```

四项默认权重依次为50%、25%、15%、10%。低置信度将分数拉向50分：q=1不收缩，q=0保留相对50分偏差的一半。组件计算保留3位小数。

例如上面的JSON：B=93.75，q=0.9，S=91.562；无历史平滑时最终显示91.6分。`focus_probability`只是最终分数/100的兼容字段，没有额外概率校准。

### 3.2 时间平滑

取当前帧之前最多3个独立观测的位置，再保留其中有效、可评分、同版本的分数；有有效时间戳时仅采用此前60秒内观测。参考值M为这些历史最终分的中位数。

```text
有历史参考：最终分=0.88S+0.12M
无历史参考：最终分=S
```

最终分限制在0–100并保留1位小数。历史帧用已处理的最终分，当前帧用冻结的原始修正分，避免重复finalize反复平滑。

### 3.3 四态判定与分数分开

不能以“≥某分就是专注”替代状态规则。先检验类别/维度，再根据置信度产生原始状态：

| 条件 | 原始状态 |
|---|---|
| 图像无效或待复核 | unscorable |
| 类别focus且q≥0.60 | focused |
| 类别distract且q≥0.75 | distracted |
| 其他 | uncertain |

稳定态规则：

- 原始uncertain或unscorable直接保留。
- 原始focused/distracted且q≥0.85，立即确认对应状态。
- 普通置信度需要最近3个独立原始观测（包含当前）中至少2个同类支持；此前证据有时间戳时也受60秒限制。
- 模型失败帧占据窗口位置但不投票；复用帧不投新票，也不挤掉独立证据。
- 复用帧沿用源帧最终分与最终状态，不重新平滑。

状态显示：focused→专注；distracted→分心；uncertain→轻微偏离；unscorable→待复核（无效图片可显示无法分析）。因此“轻微偏离”字段也包含证据不足，不能一律按分心解释。

### 3.4 重复画面

实时相似画面默认以缩略图哈希距离≤6判断；上一帧须有效且可评分。在最近模型分析后≤60秒内可复用，超过60秒强制重新请求并绕过模型缓存。复用可以延长已观测状态时长，但不能补足3张非复用明确画面的门槛。

### 3.5 会话平均分、时长和覆盖率

每帧从采集时间代表到下一帧，最后一帧代表到会话结束；每帧最多代表30秒。开始前空缺、超过30秒的缺口和结束后的未覆盖段计入unscorable。

```text
会话平均分 = Σ(可评分帧最终分×代表秒数) / Σ可评分代表秒数
总体专注占比 = focused秒数 / 完整时间轴秒数 ×100%
明确证据占比 = (focused秒数+distracted秒数)
                 / (focused秒数+distracted秒数+uncertain秒数)
```

uncertain参与平均分；unscorable不参与平均分。无可评分时间时平均分为null。四维平均也按时间加权；history中的avg_distraction_risk_score为0–100，帧distraction_score为0–1。

实时会话与最终历史使用v2覆盖率。设已用秒数t、采集间隔I、计划秒数T、提交帧数N、可评分帧数V：

```text
预期帧数 X = min(floor(max(t,0)/I)+1, ceil(max(T,0)/I))
采集覆盖率 = min(1,N/X)；X=0时取0
模型成功率 = V/N；N=0时取0
有效覆盖率 = 采集覆盖率×模型成功率
```

首帧按即时采集计算。不能只用“成功帧/提交帧”冒充覆盖率，也不能对额外提交直接用min(1,V/X)掩盖失败帧。批量build_summary最初以V/N汇总，实时session._build_payload及最终历史构建会重算v2覆盖率。

### 3.6 可靠性与积分

用于最终历史、积分与推荐的可靠记录需同时满足：

1. 评分版本为multidim-v1；
2. 有效覆盖率≥70%；
3. 存在有限的会话平均分；
4. 非复用的最终明确状态帧（focused或distracted）≥3张；
5. 明确证据时间占可评分时间≥50%。

不可靠记录可以保存供回看，但不应进入新版推荐基线；最终构建令recommendation_eligible=score_reliable。历史明确标记任一字段为false时，推荐器也将其排除。可靠性是证据充分程度，低分但证据充分的记录仍可可靠。

```text
积分=floor(实际分钟数×clamp(3×会话平均分/100,0,3)×有效覆盖率)
```

只对可靠新版记录发放；否则0积分。实际分钟数取实际经过时间与计划时长的较小值，保存到2位小数。

代码：`scoring_policy.py::score_components`、`scoring.py::_finalize_multidim_frame/stable_frame_state/build_summary`、`session.py::_build_payload`、`app/helpers.py::_timeline_metrics/build_history_entry/calculate_session_points`。

## 4. 推荐时长

### 4.1 目标分类与历史准入

推荐器本地用关键词分类，优先顺序为认知学习类→创意创作类→机械执行类，无命中默认认知学习类。示例关键词分别为学习/阅读/代码、写作/设计/PPT、整理/录入/表格。不同类别没有不同固定初始分钟数。

历史按session_id去重（同ID后出现者覆盖），无ID记录保留。排除不满足上述可靠条件的记录后，按end_time/completed_at/updated_at从新到旧排序。

- 优先取同一目标最近最多10条，至少3条才使用。
- 同目标不足3条，改取同类型最近最多10条，至少3条才使用。
- 两者均不足3条，使用默认25分钟；不是混合全体目标估计。
- 同目标匹配按目标空白规范化、截断160字符并casefold后的文本相等，不是语义相似搜索。
- 旧覆盖率记录如缺v2采集数据，会按实际分钟数和15秒旧间隔补估采集覆盖率；旧评分版本本身仍不准入新版推荐。

### 4.2 开始前推荐 recommend

可靠样本≥3条时，每条提取最长连续focused时长，取“越新权重越大”的加权中位数作为能力值。

```text
最新到最旧n条的权重：n,n-1,...,1
将(时长,权重)按时长排序
累计权重首次达到总权重一半的时长 = 加权中位数
```

若恰好到一半，返回该时长，不平均相邻两项。

存在字典时间序列时，逐项按时间排序，focused累积min(下一时间-当前时间,30秒)，其他状态清零；最后一项截止记录结束时间。没有字典观测时回退max_valid_focus_minutes。注意：推荐器此处在相邻focused之间出现超过30秒间隙时，仅截断每项贡献，并不因缺口主动清零；历史保存的_timeline_metrics会因时间缺口清零。这是当前两处实现差异。

统一取整函数：

```text
R(x)=max(max(5,配置最短分钟), min(5×round(x/5), 配置最长分钟))
```

默认配置最短1、最长180，因此通常推荐范围为5–180分钟、5分钟步长。Python round在正好一半时取偶数，如12.5→10、17.5→20。非5倍数的自定义边界可能使最终值不为5的倍数。

样本不足时返回R(25)，足够时返回R(加权中位连续时长)。代码在_default_minutes中直接写25，并未读取session_default_duration_minutes。

### 4.3 结束后的推荐 recommend_next

先将本次记录加入历史并去重筛选，因此本次可靠记录可以成为第3条样本。设P为本次计划分钟数、A为实际分钟数、S为completion_score、C为R(历史能力值)。完成率r=A/P，是计时完成率。

分支严格按下列顺序执行：

| 顺序 | 条件 | 下次分钟数 |
|---|---|---|
| 1 | 筛选后的可靠历史不足3条 | R(25) |
| 2 | 本次为旧评分版本 | R(P) |
| 3 | 本次覆盖率<70% | R(P) |
| 4 | 本次无可用总分 | R(P) |
| 5 | 本次其他可靠证据不足 | R(P) |
| 6 | r≥90%且S≥75 | max(P,R(min(max(P,C),P+5))) |
| 7 | r<70%或S<50 | min(P,R(max(P-5,min(C,P-5)))) |
| 8 | 其他 | R(P) |

因此历史不足3条的冷启动分支优先于“本次不可靠保持计划”：例如目前计划40分钟但可靠历史不足3次，下轮仍返回25分钟。

通常P为5的倍数时：表现好保持或最多加5分钟；表现差降5分钟（受最短时长限制）；中间区间保持。第7分支内部max/min会化简为P-5，因此该分支实际不受能力值C影响。P为手动选择的非5倍数时，会先按R取整，不能把注释“最多±5”当作任意输入下的严格数学保证。

阈值边界：完成率恰好70%不触发低完成率分支；分数恰好50不触发低分分支；完成率恰好90%且分数恰好75可以进入增加分支。

### 4.4 返回字段

- minutes与base_recommend：主推荐分钟数。
- challenge_recommend：R(minutes+5)，受最长值限制。
- easy_recommend：R(minutes-5)，受最短值限制。
- rest_recommend：max(5,5×round(max(minutes/5,1)/5))。默认正时长下近似按主时长的1/5再取5分钟步长，至少5分钟；如25→5、60→10、90→20。
- confidence按选中样本数给固定值：少于3条0.30；3–5条0.65；6条及以上0.85。它不是模型置信度或统计置信区间。
- sample_count/history_count是本次选中的样本量，不是用户所有记录数。current_plan分支传入空样本，因此显示0条、confidence=0.30，即使用户有其他可靠历史。
- source区分default、same_goal_history、goal_type_history、current_plan；reason/explanation保留技术解释，display_reason/feedback_text使用简短模板。
- 结束接口返回next_duration_plan，保存next_recommend、feedback_text、current_summary到历史记录。generate_session_summary同样是本地模板，没有另一次总结模型调用。

代码：`duration_recommender.py`、`app/services/focus_session_service.py::_complete_once`。
